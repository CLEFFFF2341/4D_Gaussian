# 第一优先方向：可见性约束的多运动假设光流监督

2026-10-10。交付内容是可执行的实验设计和分阶段代理 prompt；本轮做了论文、官方仓库与关键源码核查，**没有安装训练环境、运行训练或获得性能结果**。

## 先给出选择

**主基线选 MoRGS；主数据集选 N3DV；先做逐像素的高斯运动混合似然，再做目标帧可见性，跨帧联合模块放在最后。**

这里的“最优”是针对本课题的实验效率、干预位置和单卡约束的判断，不是已经证明 MoRGS 在所有动态重建榜单上最强。研究问题是：当一个像素收到多个运动不同的高斯贡献时，把监督施加到这些运动的加权平均，是否会产生错误的运动归属；保留多个候选能否改善重建？“多模态”在本方案中指多峰运动分布，不指 RGB、深度、语言等多种输入模态。

| 角色 | 选择 | 原因与限制 |
|---|---|---|
| 首选工程主干 | [MoRGS，CVPR 2026](https://github.com/LeeWonJoon9868/MoRGS) | 有训练源码、逐高斯运动与光流损失，干预位置直接。仓库报告单张 RTX A5000 测试；4090 的完整流程仍需实测。 |
| 方法的主要公平对照 | MoRGS 主干上的共享光流适配层 + 均值端点损失、稳健均值似然 | 保持数据、投影、候选、掩码和预算相同，只改变概率聚合方式；不能只打败原始配置。 |
| 第二主干／失败回退 | [Wu 等人的 4DGaussians，CVPR 2024](https://github.com/hustvl/4DGaussians) | 代码成熟，适合说明方法可移植。它是验证主干，不应称为当前最强基线。 |
| 可借鉴的流渲染工具 | [GaussianFlow](https://github.com/Zerg-Overmind/GaussianFlow) 及其 [CUDA 子仓库](https://github.com/Zerg-Overmind/diff-gaussian-rasterization) | 可借鉴逐高斯投影与贡献缓存；当前主仓库不能直接当作完整训练程序使用。不能直接覆盖 MoRGS 的定制 rasterizer。 |
| 额外近期比较 | [TAD-GS，ECCV 2026](https://github.com/vikramsandu/TAD-GS) | 放在结果成立后的外部比较阶段；先核对协议和可复现性，不与主方法同步堆叠。 |
| 固定光流教师 | [SEA-RAFT](https://github.com/princeton-vl/SEA-RAFT) | 沿用主干已有教师，避免教师升级造成归因混淆。教师误差与不确定性不能当作真实运动。 |

MoRGS 论文中的归一化混合流及其监督是最直接的研究切入点。它也有运动置信度和运动偏移，因此应尊重其完整基线，先做对照，不能把已有置信度重新命名为创新。[方法和实验来源](https://arxiv.org/html/2603.25042v1)

## 数据集与实验协议

### 主实验：N3DV 六场景

采用 [Neural 3D Video 官方仓库](https://github.com/facebookresearch/Neural_3D_Video) 与 [官方数据发布](https://github.com/facebookresearch/Neural_3D_Video/releases/tag/v1.0)。N3DV、DyNeRF 数据集、Plenoptic Video 在相关仓库中常指这套数据，不能算作三个独立数据集。

- 开发场景：`coffee_martini`、`cut_roasted_beef`。前者有复杂遮挡和液体，后者有手、工具、物体运动；液体区域单独分析，不能假设光流可靠。
- 正式场景：上述两场景，加 `cook_spinach`、`flame_salmon_1`、`flame_steak`、`sear_steak`。不同仓库的 salmon 命名需在 manifest 中映射，不能重复或漏场景。
- 正式实验使用前 300 帧；开发快速筛选使用前 90 帧。不得通过选择“效果最好的一段”替换预先指定片段。
- 以原始 `cam00` 为最终测试视角。原始相机编号可能不连续；位姿应按实际文件排序对应，不能把相机编号直接当数组下标。
- 开发时从非测试、非指定光流相机中，按相机编号选择最小的一个作为验证视角；其余可用视角训练。冻结超参数后，正式实验把这个额外验证相机放回训练集，仍只留 `cam00` 测试。
- 快速开发分辨率暂定 676×507；正式分辨率目标 1352×1014。必须先核对原视频和主干加载器的实际尺寸；任何 resize 都同步缩放内参和光流分量。
- 正式结果同时报告六场景整体、两个开发场景、四个未调参场景，避免开发场景收益掩盖泛化不足。

相机划分依据官方数据说明；分辨率、开发验证视角和预算属于本方案的实验设计，不是宣称所有论文共用同一协议。

### 第二数据集：Meet Room

从 [StreamRF 官方仓库的 Dataset 入口](https://github.com/AlgoHunt/StreamRF#dataset) 获取数据和位姿。按 MoRGS 的三场景、中央测试相机设置建立第二组正式实验。**本轮未下载完整数据，三个场景的实际目录名及中央相机原始编号须在阶段 02 核对后写死，不能猜成 cam00。**

主方法在 N3DV 完成开发后，Meet Room 不再重新搜索超参数。若数据镜像无法获取，先交付完整 N3DV 结果，并明确第二数据集未完成；不得把另一个 N3DV 别名当作补充数据。

### 不作为第一轮的选择

DyCheck 的相机运动会改变“光流大等于物体动态”的含义，不能原样使用 MoRGS 的静态相机假设。需要相机运动补偿后才适合扩展。D-NeRF 的合成场景可以做额外测试，但不足以替代真实多视角遮挡实验。另设带精确运动和遮挡真值的小型合成诊断，负责检验机制，不计作真实基准成绩。

## 最小贡献与升级顺序

**第一版只改变流监督的聚合结构。** 保留原有 RGB 重建、运动主干、密度控制和教师。把“先平均运动，再算误差”改成“分别计算各高斯解释教师运动的概率，再边缘化潜在归属”。源帧的透射率与 alpha 提供候选权重，混合权重停止梯度，尺度暂时固定。

第二版加入目标帧可见性，但必须与“同样使用目标可见性的均值流”比较。这样才能判断收益来自多假设，还是仅来自去除错误监督。

只有前两版出现稳定收益，才考虑两段轨迹共享高斯身份的联合似然。**不采用简单强迫两帧责任度相等的正则项**：遮挡变化本来就可能改变后验，硬性一致不成立。

完整公式、梯度边界、异常分量和对照定义见 [共同约束与数学定义](./共同约束与数学定义.md)。这是一套待验证假设，不能承诺涨点或顶会录用。

## 为什么第一阶段必须审计源码

已固定本次审阅的 MoRGS 版本：`5c62ae88b8fb2e3d4213329dd1ec3a61c66f8902`。

1. [训练代码](https://github.com/LeeWonJoon9868/MoRGS/blob/5c62ae88b8fb2e3d4213329dd1ec3a61c66f8902/train.py) 中光流损失实际乘以 `0.01`；配置里 `lambda_flow_rest: 0.0` 不能据此判断流监督关闭。消融必须核对真实计算图。
2. [模型属性](https://github.com/LeeWonJoon9868/MoRGS/blob/5c62ae88b8fb2e3d4213329dd1ec3a61c66f8902/scene/gaussian_model.py) 的实际位置、残差运动、偏移和置信度并不完全是同一对象。不能把一个名字含 flow 的张量直接当成精确投影位移。
3. 教师方向、流图像所在的像素网格与当前几何的 rasterization 需要端到端核对。这是待核实的坐标风险，**目前不能断言作者实现存在错误**。
4. [默认参数](https://github.com/LeeWonJoon9868/MoRGS/blob/5c62ae88b8fb2e3d4213329dd1ec3a61c66f8902/arguments/__init__.py) 的光流相机使用 `[1,4,8,13]`；要核实它们是原始相机号还是过滤后的内部编号。[场景配置](https://github.com/LeeWonJoon9868/MoRGS/blob/5c62ae88b8fb2e3d4213329dd1ec3a61c66f8902/configs/dynerf.yaml) 还会覆盖默认值。

保留原始作者版本 B0，以及审计后共享适配层的对照版本；两者的差异单列。任何投影、掩码、缓存和协议修正带来的收益，都不能计入混合似然的贡献。

## 4090 预算和止损

单卡串行运行；SEA-RAFT、SAM2 预计算后从 GPU 卸载。训练峰值目标不超过约 22 GiB，给系统留余量；这只是预算线，阶段 03 的实测决定可行性。

K=8、1352×1014、每候选 4 字节 ID + 4 字节权重 + 8 字节二维流时，仅一个候选缓冲就约 175 MB（十进制），不含梯度、排序和渲染缓存。不能用这个数字推断总显存。可分块计算损失、缓存源帧贡献，但不能为了省显存悄悄减少本方法的训练视角或迭代。

第一轮只做两个场景、一个种子、90 帧的筛选。若混合方法完全不优于稳健均值和硬分配，先诊断一次教师误差、候选截断和梯度饱和；仍无信号则停止扩规模，保留负结果。不要为“完成顶会方案”不断添加无关模块。

正式 N3DV 若跑 3 个版本×6 场景×3 种子，共 54 次序列训练；Meet Room 对应 27 次。最终方法数由筛选决定，另有开发和消融成本。运行前按实测的初始化、每帧训练、预计算、评估时间计算总预算，不能据论文吞吐量承诺几小时完成。默认第一轮可先仅完成阶段 01—05，再据结果决定后续。

项目旧记录出现过 GPU device loss。执行者应先检查当前设备健康；旧 Ex4DGS 环境与 checkpoint 不应直接当作 MoRGS 的可用环境或初始化。本轮没有触碰 GPU。
