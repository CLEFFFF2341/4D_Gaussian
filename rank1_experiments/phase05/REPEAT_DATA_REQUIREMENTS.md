# 三种子300帧复核的数据边界

此说明只约束有初筛信号后待执行的复核，不改变已冻结的90帧搜索。

实测 `manifests/splits_final.json` 中，两个开发场景的 `train` **均包含cam01**，`validation=[]`，流视角运行下标为 `[1,4,8,13]`。这是阶段03面向cam00正式测试的原B0协议，不能直接用于仍以cam01选参/复核的阶段05。

后续300帧复核必须另建数据树及划分，训练排除cam00和cam01，验证为cam01；保留物理相机ID，再核验运行下标。不能只添加一个validation目录而继续从含cam01监督的旧final checkpoint恢复。

**所有 seeds0/1/2 均需在新的独立训练划分上生成共同frame1初始化。** 现有 `runs/B0/final/coffee_martini/seed0_dense` 及其他包含cam01训练的正式初始化不能当作阶段05的无泄漏seed0初始化。正式B0数据、成绩和checkpoint继续冻结。

训练flow/SAM缓存可按真实相机ID、输入帧和分辨率核验后复用，不能沿用错误数组下标，也不能把dev90缓存强当300帧缓存。需要核查新protocol对应的缓存路径与extent。评价代理区域必须重新在正式cam01图像网格上冻结。

共享K64头在1352×1014上的完整优化资源尚未实测。若资源不支持，所有方法/场景/种子使用同一个受限分辨率，并完整报告；不能让M和控制采用不同协议。选定全局λ/σ冻结，不逐场景或种子重新搜索。

此队列若完成seed0初筛并发现信号，停留在阶段05的 `REPEAT_REQUIRED`；这不是阶段05门槛通过或阶段06授权。
